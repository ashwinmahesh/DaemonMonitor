# Working on Daemon Monitor

Read README.md. Keep the three-row popover compact (AI Bridge, Image Generator, Voice Generator); use shared Service/Queue/Processing column headings, health dots directly beside names, and one settings button per row. Startup configuration uses aligned form rows with paths/environment in an expandable section. Native SwiftUI/AppKit lives in Sources/DaemonMonitor.swift; Tools/MakeIcon.swift generates the app icon from the matching activity symbol; the Python standard-library lifecycle adapter is Resources/control.py. Prefer argument arrays, never shell interpolation/evaluation.

The user manages service startup manually; services load requested models at runtime. Preserve pre-existing services and active jobs. Never clear queues, submit inference jobs, download models, change model environments, or stop services from other checkouts/test ports to validate the monitor. After testing, stop only generators/queues started for that test. Busy generators must refuse stop; never force-kill them. ai-bridge clean shutdown can interrupt provider work, so use fixtures to test it and leave the user's running bridge alone.

Saved configuration applies at the next start; retain actual running endpoints. Synchronize the shared queue port and project folder within each image/voice family. Keep private settings, process records, credentials and logs in Application Support, outside the source tree.

Image/voice use the shared-queue runtime-model contract: verify stable generator/queue identity, project, version and shared scope, never an active model as identity. No model-bound compatibility routing. Loading/switching/preview work is busy; recheck before shutdown. A blocked model job is not a global outage, and an offline queue HTTP API does not break the generator's direct SQLite access. The monitor has no model picker or default-model concept. Processing pauses/resumes through each project's existing pause API (generator first, queue fallback, after the identity check); it never cancels jobs, and immediate/Run Now work still runs while paused. Never pass model overrides in startup arguments/environment; obsolete stored model values are ignored. Active model information is read-only.

Match each actual published health contract: ImageGen uses `version`, `project_dir`, and generator service `imagegen-generator` (optional `role:generator`); VoiceGen uses `api_version`, `project`, and generator service `voicegen-service` with required `mode:generator`. Voice queue remains `voicegen-queue` with `role:queue-crud`. Do not assume ImageGen's field names apply to VoiceGen; verify live/source health alongside fixtures when integrating either service.

Performance views live in Sources/Performance.swift and the read-only collector in Resources/metrics.py. Record metrics only for running tools, including their live children without counting monitored queues twice. Skip GPU queries when all tools are stopped; preserve gaps between runs and unavailable counters. Keep health polling separate from 15-second foreground / 60-second background metrics sampling, and retain only seven days of local history. Run both Python tests and `zsh Tests/run_monitor_tests.sh` for metrics/controller changes.

Validate lifecycle changes with `python3 -m unittest discover -s Tests -v`, then build with `./build.sh`. Visually inspect the popover/settings when the Mac is available. `./install.sh` deploys to ~/Applications and installs the monitor's own login agent; it must not restart monitored daemons. Record actual verification and limitations in verification.json. Do not claim UI checks or real inference were performed unless they were.
